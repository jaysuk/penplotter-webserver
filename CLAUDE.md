# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Flask + Flask-SocketIO web UI for HPGL pen plotters, run on a Raspberry Pi (the "PiPlot" branch, adapted for the [Pi Plot shield](https://github.com/ithinkido/PiPlot)). It uploads SVG/HPGL files, converts SVG to HPGL with vpype, and streams HPGL to a serial plotter with several flow control schemes. Originally https://github.com/henrytriplette/penplotter-webserver (since rewritten there with a Vite/TypeScript frontend, so changes do not merge cleanly); `ithinkido/penplotter-webserver` hosts the per-OS install branches.

## Commands

```bash
pip install -r requirements.txt -r requirements-dev.txt   # vpype needs Python >= 3.9
python3 main.py                  # serves on :5000; WEBPLOTTER_DEBUG=1 enables the Flask debugger
pytest                           # whole Python suite (no hardware needed)
pytest tests/test_send2serial.py -k stop      # a single test
node --test tests/hpgl_viewer.test.js tests/theme.test.js tests/layout.test.js   # JS tests (Node >= 18)
bash -n install.sh               # the installer can only really be tested on a Pi / the arm CI image
```

`tests/test_convert.py` runs real vpype and is skipped when vpype is not installed. There is no linter configured. The styles are hand written, with no build step: `static/css/theme.css` (fonts, colour tokens) and `static/css/console.css` (layout and components).

## Architecture

**Request flow.** `main.py` is the only Flask app. It `chdir`s to its own directory on import because `config.py`, `send2serial.py` and `convert_vpype.py` use relative paths (`config.ini`, `uploads/`). Importing `config.py` has side effects: it prints, and creates `config.ini` with defaults if missing.

**Plotting.** `/start_plot` validates input, takes `plot_lock` (one plot at a time) and runs `plot()` in a Socket.IO background task, which calls `send2serial.sendToPlotter`. `plot()` always releases the lock and emits `lock_edit: off` in a `finally`. `/stop_plot` only sets `globals.printing = False`; the send loop notices and exits. `/pause_plot` and `/resume_plot` set `globals.paused`, which makes the send loop idle (the plotter still draws what is in its buffer). Do not hold the HTTP request open for the duration of a plot.

**Plot state for late clients.** `plot()` passes a `PlotEvents` object (not the raw `socketio`) to `sendToPlotter` and tasmota; it forwards each event and records the log, progress, byte count and buffer size in `globals`. The `connect` handler emits `plot_state` (running, paused, file, progress, buffer size, log) so a refreshed page or a second device can show and stop the running plot; `start`, `end`, `pause` and `resume` broadcast `plot_state` without the log. `static/main.js` `applyPlotState` applies it. New plot-related events from `send2serial` must go through the object it is given, or a reconnecting page will not see them.

**`send2serial.py` flow control** decides what is possible, and several branches depend on it:
- `CTS/RTS` and `Software`: the plotter is asked for its buffer size and free space (`ESC.L`, `ESC.B`); this feeds the buffer chart. `use_buffer` is true only for these.
- `XON/XOFF` (driver handshaking), `NONE` (none) and `HP-IB` (Plug n Plot, fixed 9600 baud, 1 byte at a time) have no buffer feedback. The UI sends `None`; `sendToPlotter` normalises it to `NONE`.
- CTS is polled by hand because of a pyserial bug with `rtscts`, so never enable `rtscts` for CTS/RTS mode.
- Stop sends `ESC.K` + `PU;` only when `use_buffer` is true. This is untested on real hardware.

**History and power-off.** `history.py` is a SQLite log (`history.db`, next to `config.ini`, copied by the installer's update path). `plot()` records start and end (completed / stopped / failed; `init()` marks plots left `running` as `interrupted`). History errors are printed and swallowed: they must never stop a plot. Each row keeps the form the plot was started with (`options`, JSON) and the file's size; `POST /replot` (`job`) feeds `job_values()` to `begin_plot()`, the same path as `/start_plot` (`plot_request()` validates, `claim_plot()` takes the lock), so a stored plot gets the same checks as a new one. Rows from before `options` existed fall back to the port, baud and flow control columns. `history.NEW_COLUMNS` is how a column is added to an existing database. `plot()` decides the outcome right after `sendToPlotter` returns, then waits `tasmota.off_delay()` before switching off; `globals.stop_requested` and `globals.plot_finished` let `/stop_plot` skip that wait (and not send a "Cancelled" message for a plot that already finished) or cancel the plot during the start-up wait. The delay is a delay, not an idle check: no verified HP-GL query tells when drawing has finished.

**Queue.** `plot_queue.py` (named so because `queue` is a stdlib module Flask-SocketIO imports) keeps `queue_items` in `history.db`. `/queue/start` sets `globals.queue_active` and runs `run_queue()` in a background task; it calls `plot()` once per item, taking the lock each time (`claim_plot`). While `queue_active`, `begin_plot` refuses a manual plot (409), so the gap between two items cannot be taken, and queued files cannot be deleted. `plot()` takes `power_on` (false when the previous plot left the plotter on), `keep_power` (asks the queue whether another plot follows: then Tasmota is not switched off and `paper_change` waits for Resume with `wait_reason='paper_change'`) and returns `'completed'`, `'stopped'` or `'failed'`. **Stop holds the queue**: `/stop_plot` sets `globals.queue_hold`, the plot that was running goes back to `waiting` at the top (a completed one leaves the queue), and `/queue/start` carries on from there. A failed plot, or a file that was deleted, holds the queue too. Items hold the same options dict as a history row (`plot_request()` validates both). The page gets `queue_state` events; `plot_state` carries `queue_active`.

**Resume.** `sendToPlotter` keeps `globals.sent_offset` (bytes written) and `globals.buffer_used` (bytes the plotter is known to still hold, buffer flow control only; with `ESC.K` on stop they are never drawn). `plot()` stores `sent_offset - buffer_used` as the history row's `resume_offset` for a stopped or failed plot, counted in the file that was made from the job's options (the original, or the copy with the chosen pens), so it is the same coordinate space however often a plot is resumed. `POST /resume_job` (`job`, optional `rewind` bytes) passes `resume_from` to `plot()`, which writes `cache/plots/<name>-resume.hpgl` with `hpgl_analysis.resume_file`: `IN;`, the repeated set-up commands (`SETUP_COMMANDS`), `VS`, `SP<pen>` (never `SP0`), `PU;PA x,y;` (then `PD;` and `PR;` if the file was in that state) and the rest of the file from the start of the command at the offset (it goes back, never forward). A resumed plot's own offset is mapped back through `resume_start`/`resume_skip`; the old row's offset is cleared once the new plot has sent something, so it cannot be resumed twice. `can_resume` needs the file to have the size it had when plotted. Without buffer feedback the real position is unknown (the plotter keeps drawing its buffer after Stop), hence the rewind choice in the UI. Untested on real hardware.

**CalComp `.cal` files.** Plain-ASCII, `;`-terminated commands (`R2; H; F1; F10,16; Cx,y; K; I; F0;`), not HP-GL. They can be uploaded, selected, plotted, queued and plotted again (`PLOT_EXTENSIONS` in `main.py`, `send2serial.is_cal`), and are sent byte for byte. `sendToPlotter` then skips everything HP-GL: the `IN;ESC.I80...` set-up (`open_port(init=False)`), the `IN;OI;` identification query and all buffer queries, so only `XON/XOFF` (the Model 84 handshake) and `NONE` are allowed (`CAL_FLOW_CONTROLS`, checked in `plot_request` and in the sender). Stop sends `H;` (pen up, queued behind the plotter's buffer). There is no server-side analysis (so no time left), pen choice, pen-change pause or resume (`can_resume` is false, no `resume_offset` is stored), and a lost connection fails the plot instead of reconnecting: the plotter's pen, stall and speed cannot be put back from outside. Untested on a real CalComp; serial settings are 8N1 at the chosen baud rate. **Preview:** `parseCAL` in `static/hpgl_viewer.js` (`loadHPGL(text, 'cal')`, picked by the file name in `loadPreview`) reads it in the browser into the same `paths`/`route` as HP-GL, scaled from 0.1 mm steps to HP-GL units. `C x,y` only stores a pair; `K` moves to it (absolute), `J` relative; `H`/`I` lift/lower the pen; `F n` picks a pen (`F 10,n` is speed); `R` lifts the pen. A pen-down move to the same place is a dot. `T`, `N`, `W` and `M` (origin, scale, window, point marks) are listed as ignored, since they would place the drawing wrongly. The format notes come from the plotter's manual and have not been checked against a real plot; there is no paper outline and `cursor_ok` stays false, so no live cursor.

**Reconnect.** A `SerialException`/`OSError` inside the send loop calls `send2serial.reconnect()`: the plot is held (`globals.paused`, `wait_reason='disconnected'`), the port is opened again with growing pauses (`RECONNECT_DELAYS`, given up after `RECONNECT_GIVE_UP`, which fails the plot), then `wait_reason='reconnect'` waits for the user to press Resume (`/resume_plot` is refused with 409 while `disconnected`). Nothing is re-sent silently: the sender goes back to the start of the command at `sent - unprocessed` (buffer flow control: the plotter's known buffer content plus the last chunk; otherwise `REWIND_NO_FEEDBACK` bytes, `REWIND_HPIB` for HP-IB), never before the last pen change that was passed, sends `hpgl_analysis.resume_preamble` first (the loop's `pending` bytes, which do not count towards file offsets) and carries on. The plotter may or may not have drawn what was in its buffer, so the last strokes can be drawn twice; that is chosen over a gap. A buffer query that times out (`HPGLError`) is still a plain failure, not a disconnect. Untested on real hardware; `tests/fake_serial.py` can break a port (`break_at`, `open_failures`, `failures_after_break`).

**Storage.** `/update_files` adds `size` and `mtime` to each file. `/storage` reports `shutil.disk_usage` and what uploads, `cache/` and `history.db` use. `/delete_old_files` (`days`, 1 to 9999) and `/clear_cache` take `plot_lock` for the duration (so a plot cannot start half way) and refuse while a plot or the queue runs; files that are in the queue are never "old".

**Status API.** `GET /api/status` (behind the same login) returns `plotter`, `state` (`idle`, `plotting`, `paused`, `pen_change`, `paper_change`, `disconnected`, `reconnect`), `plot` (the `plot_state` the page gets, without the log), `queue` and `last_plot`. Read-only; keep it small and stable, other programs read it.

**Backup and restore.** `backup.py` is the pure part. `/backup` (GET, `?uploads=1`) zips `config.ini`, `history.db` (copied with sqlite's backup API under the history lock, so it includes the presets and the queue), optionally `uploads/`, and a `manifest.json` (`app`, `format`); it streams from a temp file that a generator's `finally` removes. `/restore` takes a zip from outside, so `backup.inspect` checks every member name against a whitelist (`config.ini`, `history.db`, `manifest.json`, `uploads/<name>.svg|hpgl`: no folders, `..` or backslashes), the sizes, and the manifest; the config goes through the same `CONFIG_FIELDS` validators as a save (unknown settings are ignored, an empty write-only value keeps the current one, a login is restored only with both parts); the database must pass `integrity_check`, have a `jobs` table and no triggers or views. Only after all of that is anything applied: `store_config` (shared with the save route), `source.backup(conn)` into the live database followed by `history.init()`/`plot_queue.init()`/`presets.init()` (adds columns and tables an older backup lacks), then the files. Restoring takes `plot_lock`, so not while plotting. The zip contains the passwords of `config.ini`.

**Analysis, time left and pens.** `hpgl_analysis.py` is a pure-Python, streaming HPGL parser (`iter_commands` yields byte offsets, `State` replays the pen, including circles and arcs). `analyze` returns bounds, pen-up/pen-down length, a rough time estimate and `segments` (one per `SP n`, in plotting order) plus `marks` (offset -> estimated seconds, for the time left). `analyze_cached` keeps the result in `cache/analysis/` until the file changes; files over `MAX_ANALYSE_BYTES` are not analysed (plots still run, without ETA or pen pauses). The time model is a guess; `history.correction()` scales it by the median of drawn/estimated over the last completed plots (`jobs.estimate_s`, `jobs.drawn_s`). vpype writes layers as `SP<layer>` and everything after the first move in **relative mode (`PR`)**, so code that skips or reorders segments must resync with an absolute move (`filter_pens` does). `/analyze` answers from the cache only while plotting, so it does not compete with the serial loop. `sendToPlotter(..., analysis, pen_pause, correction)` emits `eta`; with `pen_pause` it stops at each pen change (waits for the buffer, sends `PU;`, sets `globals.paused` with `wait_reason='pen_change'` and `wait_pen`, emits `pen_change`) and `/resume_plot` continues. Never send `SP0` for a manual pen change: a plotter with a hand-fitted holder would try to put the pen away. `/start_plot` accepts `pens` (e.g. `1,3`, plotted from a filtered copy in `cache/plots/`, deleted afterwards) and `pen_change` (`auto` or `pause`, default from `[plotter] pen_change`). Waiting time is excluded from `globals.drawn_seconds`.

**Manual pen control.** `plotter_control.py` builds the HPGL for jog, pen up/down, pen select, go to origin, trace the plot area and the `OA;` position query; only validated numbers reach a command. `POST /plotter/<action>` runs it through `send2serial.run_commands`, which opens the port with `init=False` (no `IN;`, so the plotter keeps its state) and takes `plot_lock` non-blocking (409 while a plot runs). Use `[0-9]`, not `\d`, in validation regexes: `\d` matches other scripts' digits, which `int()`/`float()` accept.

**Serial ports.** `send2serial.listComPorts` lists `/dev/serial/by-id/` names (via `byIdPorts`) instead of the `/dev/ttyUSBx` they point to; `/update_ports` also appends the saved default port if it is missing, so an unplugged adapter or an old `/dev/ttyUSB0` setting stays selectable.

**Realtime events to the UI** (all payloads are `{'data': ...}`, the UI reads `msg.data`): `status_log`, `error`, `bytes_written`, `print_progress`, `buffer_size`, `buffer_space`, `end_of_print`, `lock_edit`, `eta` (`{remaining, total}` seconds) and `pen_change` (`{pen}`; `PlotEvents` also broadcasts `plot_state`, which carries `wait_reason` (`pen_change`, `paper_change`, `disconnected`, `reconnect`), `pen`, `eta` and `queue_active`, whenever the sender emits `pen_change` or `wait_change`), and `queue_state` (`{active, message, items}`). The `connect` handler sends the current `lock_edit` state so a refreshed page is correct.

**Conversion.** `convert_vpype.convert_file` builds a vpype command line and runs it in-process (`vpype_cli.execute`). The output name encodes the options (`<file>-<size>-<orientation>[-options]-<device>.hpgl`). `layout -m 0` deliberately scales the drawing to fit the page; the page is added as a rectangle on layer 1000 so layout fits the page rather than just the ink, and `write --center` then centres the ink on the paper (so layout alignment has no effect). Page options are applied to that whole page before layout: `rotate` (0/90/180/270, vpype `pagerotate`), `mirror_x`/`mirror_y` (`scale -- -1 1`; negative factors need `--`) and `margin` (mm, `layout -m <n>mm`, 0 to 50). `main.conversion_options()` validates the form and `run_conversion()` calls `convert_file`; `convert_vpype.output_name()` gives the file name a set of options produces, and `output=` writes somewhere else. vpype 1.15 has no G-code reader and no `mp4200` device profile. **Preview:** `/preview_conversion` converts into `cache/preview/` (same validation, same name as a real conversion), returns the analysis summary and the UI draws it with the HPGL viewer; `/save_preview` moves it into `uploads/` (409 for the file being plotted), unsaved previews are deleted after a day. Preview names are checked with `HPGL_NAME_RE` and looked up in the preview folder only. Converting is CPU heavy and runs in the request thread, even while plotting. **Presets:** `presets.py` keeps named sets of conversion options in a `presets` table of `history.db` (through `history.database()`, which shares the history's lock; the installer's update already copies the file). They are stored in the shape of the convert form (`main.preset_form`), after the same `conversion_options()` validation, so applying one is just filling the form in. **Text drawings:** `/create_text` writes an svg (`text-<first line>.svg`) from typed text; `text_drawing.py` is the pure part (validation, file name, the vpype command line, the fit check) and `convert_vpype.create_text` runs it. vpype evaluates `%expr%` and `{property}` in command arguments, so those characters are refused; everything else is quoted with `shlex.quote` and passed after `--`. Negative arguments (`translate`, `scale`, `rotate`) always need `--`. A line that does not fit between the margins is an error rather than being clipped. **PDF import:** uploading a `.pdf` runs poppler's `pdftocairo -svg -f 1 -l 1` (from `cache/pdf/`, 120 s timeout, `%PDF-` checked first) and keeps only `uploads/<name>.svg`; the page only offers `.pdf` when `pdftocairo` is on the PATH, and `install.sh` installs `poppler-utils` on a fresh install and on update (non-fatal). Filled shapes come out as outlines. Tests fake `pdftocairo`; it has not been run against real poppler output in this repository's tests. Custom vpype commands are inserted into the command line, so `main.py` only allows `[A-Za-z0-9 ._=+-]` and blocks `eval`, `script`, `read`, `write`, `forfile`, `include`, `show`.

**Configuration.** `config.config` is one shared `ConfigParser`. `notification.py`, `tasmota.py` and `send2serial.py` read it at call time, so a save from the UI applies without a restart. `save_configfile` validates against `CONFIG_FIELDS`, escapes `%` (configparser interpolation), and writes atomically. Keep new settings in `CONFIG_FIELDS` and add a matching `name="<field>"` input to the config modal in `index.html` (a test fails if one is missing). The login (`[auth]`) is edited there too: the password is write-only (`WRITE_ONLY_FIELDS`, never returned by GET, empty means keep), and an empty user name removes the `[auth]` section. Read config values that may be hand edited through `config_value()`, which tolerates a single `%`. **Notifications**: everything goes through `notification.send(event, message, **data)` (events `start`, `finish` (also stopped), `error`, `attention` (pen or paper change, plotter back), `progress`; the toggles are in `[notifications]`, and a test has `SYNC = True`). Delivery is a background worker with short timeouts to Telegram, a webhook (JSON POST) and MQTT (`<topic>/<event>`, via `paho-mqtt`, imported lazily); a failing channel only prints its exception class, never details (they could contain the password). `telegram_sendNotification` is still the Telegram channel, so tests patch that. A failed plot sends one `error` from `plot()` with the reason, so the sender must not also send its own. `/action_test_notification` sends a test to every channel set up.

**Viewer.** `static/hpgl_viewer.js` parses the text in the browser into `paths` (drawn polylines, per pen) and a `route` (every move in file order, as parallel arrays: `seg`, `meta` = pen*2+down, `off` = where the command starts in the text, `cum` = length so far). Circles and arcs (`CI`, `AA`, `AR`) are drawn as 5 degree chords (`arc_points` in `hpgl_analysis.py` is the same maths, so lengths agree). The class does zoom and pan (wheel, drag, pinch, double-click to fit), a pen legend (`penList`, `setPenVisible`), dashed pen-up travel, a hover crosshair that reports mm from the drawing's lower left, and a cursor (`setCursor`, `setCursorOffset`) used by the replay and by "Watch the plot". The replay time is the route length at 380 mm/s times the chosen factor: it is for looking, not a time estimate. The paper outline (conversion preview only) is centred on the drawing, because `write --center` does that; its size comes from the form's size, orientation and rotate. `plot_state.cursor_ok` is true only when the bytes sent are offsets in the file in the list (no chosen pens, not a resume), so the live cursor is not shown for other plots. The offsets are character positions, which equal byte positions for ASCII HPGL. `tests/hpgl_viewer.test.js` drives the class with a fake canvas.

**Theme.** `static/theme.js` (loaded in `<head>`) keeps Light/Dark/Auto in `localStorage` (default Auto) and sets `data-theme="light"` or `"dark"` on `<html>`, always one of the two. `static/css/theme.css` holds the self-hosted fonts (`static/vendor/fonts/`, OFL, README there) and the colour tokens for both themes as custom properties (`--bg`, `--panel`, `--accent`, `--ok`, ...); `console.css` only uses those tokens, so a new colour belongs in `theme.css` for both themes. The preview and Smoothie chart canvases read tokens at draw time (`buffer_chart.js` `chartColour`). The preview canvas stays white: it is the paper. Nothing has been looked at on a real phone or tablet yet; it was checked in desktop Chrome at 400 px and 1440 px.

**Frontend** has no build step: `templates/index.html` loads pinned, self-hosted libraries from `static/vendor/` (UIkit 3.7.2, jQuery, Dropzone, axios, socket.io 3.1.3) then `static/main.js` (actions), `utility.js` (helpers, `escapeHtml`, `errorMessage`, the file row markup), `hpgl_viewer.js` (preview) and `buffer_chart.js`. UIkit stays for the form controls, grids inside panels, modals, tooltips, notifications and icons; `console.css` restyles it under `body.console`. UIkit 3.7.2 has a limited icon set (`eye` does not exist and renders invisibly), so check `static/vendor/uikit-icons.min.js` before using an icon; the panel titles use an inline SVG sprite at the top of `index.html` instead. Always escape filenames and server messages (`notify` escapes; use `.text()` rather than `.html()` for user data).

**The Console page** (see `PLAN-console-ui.md` for what is done and left). The page is a header, a *transport bar* (`#transport`: state pill, file, progress, pen, bytes, time left, Start/Pause/Resume/Stop) and three columns `.cs-col[data-col=left|center|right]` of `section.cs-panel[data-panel=<id>]`. Panels: `files`, `upload`, `queue` (left), `preview`, `status`, `history` (centre), `settings`, `control`, `buffer`, `system` (right). Each has a `.cs-phead` and a `.cs-pbody` and a `--m-order` for the single-column phone layout. The transport bar reuses the classes `main.js` already updates (`.printProgress`, `.selectedFilename`, `.startPlot`, `.pausePlot`, `.resumePlot`, `.stopPlot`, `.lock-edit`, `.unlock-edit`) plus `.penText`, `.pctText`, `.bytesText`, `.etaClock`; `applyPlotState` calls `updateTransport` and the `print_progress`/`bytes_written`/`eta` handlers call `setProgress`/`setBytesWritten`/`setEta`. A pen or paper change still opens `#modal-wait` and also shows in `#transportMessage`. The selected file row has `li.is-selected`.

**Preview panel.** The viewer lives in the `preview` panel (there is no preview dialog any more); `#previewStage` holds `#hpglCanvas` and an empty-state message, and `.has-drawing` on the stage shows the canvas (CSS hides it otherwise, because the viewer sets `display: block` inline). `showPreview(title, url, conversion, watch, quiet)` in `main.js` is the one way in: selecting a file calls it with `quiet` (through `previewSelected`; it does nothing while an unsaved conversion is shown, or the panel is hidden or folded), the image icon in the file list, Convert's Preview button and Watch the plot call it without `quiet`, which closes `#modal-convertFile` and brings the panel back (`WebPlotterLayoutUI.reveal`, which unhides, unfolds and scrolls to it). A conversion that is not saved shows a "Not saved yet" tag with Change options (reopens the convert dialog) and Save as HPGL; looking at another file replaces it. `panelschanged` (fired by `layout-ui.js` after every change) makes `onPanelsChanged` load the selected file when the panel has come back and stop a replay nobody can see. The canvas is as wide as the stage: `watchPreviewSize` refits the drawing with a `ResizeObserver` when the width changes. The Watch the plot button (in Print status) toggles: the cursor follows the bytes sent until pressed again or the plot ends. `bytes_written` arrives as text (`"42%, 420 bytes written."`), so use `setBytesWritten`/`followPlot`, which parse it. 
**Panel layout.** `static/layout.js` is the pure part (no DOM, tested in `tests/layout.test.js`): the panel ids and their default columns, `normalise` (anything stored or hand made becomes a valid layout: unknown and repeated panels dropped, a missing panel goes back to its own column, widths clamped to 220 to 560, another `v` gives the default), `withVisible` (the order found in the page after a drag), `shift` (arrow keys), `setHidden`, `setFolded`, `setWidth`, and `load`/`save`/`forget` for `localStorage` key `webplotter-layout` (blocked storage gives the default). `static/layout-ui.js` applies it and runs right after the columns in `index.html` so the saved layout is in place before first paint. It adds a handle, a fold and a hide button to each `.cs-phead`, the chips bar (`#panelShelf`, fixed order, a pressed chip means shown), the dividers (`[data-split=lw|rw]`, drag or arrow keys), keyboard moving (arrows on the handle) and "Reset layout" (`.resetLayout`, also in the settings dialog). Dragging is UIkit's sortable (`group: panels`, one list per column, handle `.cs-grip`), switched on at `DOMContentLoaded`, and it works with mouse and touch. **A hidden panel is moved into an off-screen container (a `div[hidden]` that `layout-ui.js` adds right after `#cols`) rather than hidden in place:** it stays in the page, so `main.js` keeps updating it by selector, but its column can be truly empty, and UIkit's sortable did not accept a drop into a column whose only children were hidden panels. Under 860 px the columns are `display: contents`, the order comes from `--m-order`, and the handles, dividers and arrow keys are off (fold and hide still work). To add a panel: put a `section.cs-panel[data-panel]` in `index.html`, add its id to `DEFAULT_COLUMNS` in `layout.js` (a test checks the two agree), and give it a `--m-order`.

## Security model (keep it intact)

- Never build a path from request data directly: use `upload_file_path()` in `main.py`, which keeps names inside `uploads/`.
- Validate with `fullmatch`, not `match`: `$` accepts a trailing newline.
- Optional HTTP basic auth via an `[auth]` section in `config.ini`; `before_request` also refuses cross-origin state-changing requests. Socket.IO connections bypass `before_request`, so `on_connect` checks auth separately. State-changing routes are POST-only.
- Debug mode, the reloader and a fixed secret key are intentionally off.

## Install and deployment

`install.sh` is run as `curl | bash`, so use `exit`, never `return`. It always installs the `PiPlot` branch of `jaysuk/penplotter-webserver` whatever the OS release (the sources run on any Python >= 3.9.2); override with `WEBPLOTTER_REPO` / `WEBPLOTTER_BRANCH`, and `WEBPLOTTER_NO_REBOOT=1` skips the final reboot. Installer output goes through the helpers at the top (`step`, `run_spin`, `ok`, `warn`, `note`): numbered steps, a spinner with elapsed time, and command output logged to `~/webplotter-install.log` (shown on failure). `ensure_sudo` asks for the password in the foreground and keeps it alive, because a prompt hidden behind a spinner looks like a hang. The installer refuses `sudo bash install.sh` and a `$HOME` not owned by the current user (the service file is written from `whoami` and `$HOME`; CI legitimately runs as root, so root only warns). `/action_reboot` and `/action_poweroff` check `sudo -n -l <cmd>` first and return a 500 with an explanation when passwordless sudo is missing. Never run `sudo` for the first time inside `run_spin`, and keep colours/cursor codes behind `ISTTY` (CI is not a terminal). All Python dependencies, including vpype, must be listed in `requirements.txt`: the installer installs that file line by line and nothing else. The update path clones into `webplotter.new` first, copies `uploads/` and `config.ini` across, and keeps `webplotter.old` on failure. `.github/workflows/install_test.yml` installs the pushed commit on emulated Pi Zero images (32 and 64 bit), starts the server, converts an SVG through it, then runs the installer again to check an update keeps uploads and config; it can only run on GitHub. `.gitattributes` forces LF for shell, service and Python files: the Pi breaks on CRLF.

## Testing notes

`tests/sim_plotter.py` is a simulated HP-GL plotter on a pseudo-terminal (Linux/macOS), and `tests/pi_serial_check.py` drives a throwaway copy of the app against it with the real pyserial: a whole plot, pen change pause, stop then resume, an unplugged and re-plugged port, and the queue. Run it on a Pi after changing `send2serial.py`. It has no CTS line, so use Software or XON/XOFF flow control with it, and it says nothing about what a real plotter does.

Tests that replace `send2serial.sendToPlotter` must use `monkeypatch.setattr` (assigning the attribute leaks into later tests), and fakes take `**kwargs` because `plot()` passes `analysis`, `pen_pause` and `correction`. Tests that start the real sender in a thread must make it a daemon and stop it on teardown, or a failure leaves the run hanging at a pen change.

New Python modules must be added to `SOURCES` and `APP_MODULES` in `tests/conftest.py`. `tests/conftest.py` copies the sources into a temp dir and imports them there with a fake pyserial (`tests/fake_serial.py`) and a stub converter, so tests never touch the repo's `config.ini` or `uploads/`. The `app` fixture resets uploads, config, serial state and `globals` for each test. When changing the plot lifecycle, drive it with the `slow_plot` fixture rather than sleeping.

`config.py`, `send2serial.py` and `convert_vpype.py` were originally committed only as compiled Python 3.11 `.pyc` files and were rebuilt from the bytecode (verified bytecode-identical before any fix). The upstream per-OS install branches (`bookworm_64` etc. on `ithinkido/penplotter-webserver`) still ship compiled copies, but this repository no longer installs from them.
